# 프로젝트 제안서

## 프로젝트명

**DORA Lens** — GitHub 저장소의 DORA 지표 자동 수집·시각화 도구

## 문제정의

- 소규모 팀이나 학생 프로젝트는 "우리가 얼마나 자주, 얼마나 안정적으로 배포하고 있는가"를 수치가 아니라 감으로 판단한다. 그래서 회고에서 개선할 지점을 구체적으로 짚기 어렵다.
- 배포 성과를 재는 표준 지표로 DORA 4대 지표(Lead Time for Changes, Deployment Frequency, MTTR, Change Failure Rate)가 있지만, 이를 측정해 주는 상용 도구는 비용과 초기 설정 부담이 커서 작은 팀이 쓰기 어렵다.
- 계산에 필요한 데이터(커밋, 배포 기록, 이슈)는 이미 GitHub에 쌓여 있다. 다만 여러 API에 흩어져 있어 직접 모으고 계산해야 한다.

**목표**: 저장소에 워크플로우 파일 하나만 추가하면 DORA 지표가 주기적으로 수집되고, 대시보드와 주간 보고서로 바로 확인할 수 있게 한다. 별도 서버나 유료 서비스 없이 GitHub Actions와 GitHub Pages만으로 동작해야 한다.

## 핵심 기능 3개

1. **지표 자동 수집** — GitHub Actions가 스케줄에 따라 GitHub REST API(Deployments, Commits, Issues)를 조회해 DORA 4대 지표를 계산하고 JSON으로 저장한다.
2. **대시보드 시각화** — 수집된 JSON을 Chart.js로 그려 GitHub Pages에 게시한다. 현재 값, DORA 성능 등급(Elite/High/Medium/Low), 기간별 추이를 한 화면에서 본다.
3. **주간 보고서 자동 생성** — 매주 지표 요약과 전주 대비 변화를 Markdown 보고서로 만들어 저장소에 커밋하고, 원본 데이터는 워크플로우 아티팩트로 보관한다.

## 기술 스택

| 영역 | 기술 | 선택 이유 |
|---|---|---|
| 수집·계산 | Python 3 (표준 라이브러리) | 의존성 설치 없이 어떤 러너에서도 실행 가능 |
| 자동화 | GitHub Actions | 스케줄 실행, 아티팩트 저장, 저장소 권한 토큰 기본 제공 |
| 데이터 원천 | GitHub REST API | 배포·커밋·이슈 데이터를 추가 계측 없이 사용 |
| 시각화 | Chart.js, HTML/CSS | 빌드 과정 없는 정적 페이지로 충분 |
| 호스팅 | GitHub Pages | 무료, 저장소와 같은 곳에서 배포 이력 관리 |
| 계획·추적 | GitHub Issues / Projects / Milestones | 백로그와 스프린트를 코드와 같은 곳에서 관리 |

## 16주 마일스톤 초안

| 주차 | 목표 | 산출물 |
|---|---|---|
| 1 | 개발 환경 설정, 프로젝트 제안 | 저장소, 제안서 |
| 2 | DORA 지표 정의 및 수집 프로토타입 | 수집 스크립트, 워크플로우, 대시보드 시안 |
| 3 | 계획·추적 체계 구축 | GitHub Project, 백로그, 라벨, 마일스톤 |
| 4 | 수집 로직 정교화 (배포–커밋 매핑, 봇 커밋 제외) | Lead Time 계산 개선 |
| 5 | 장애(incident) 추적 흐름 정리 | 이슈 템플릿 연동, MTTR/CFR 계산 검증 |
| 6 | 단위 테스트 및 CI 구성 | 테스트 코드, CI 워크플로우 |
| 7 | 대시보드 1차 완성 | 추이 차트, 등급 표시, 표 보기 |
| 8 | **중간 점검** — 자기 저장소에 4주 이상 적용한 결과 회고 | 중간 보고서 |
| 9 | 다중 저장소 수집 지원 | 설정 파일, 저장소별 비교 화면 |
| 10 | 재사용 가능한 Action으로 패키징 | `action.yml`, 사용 예시 |
| 11 | 지표 악화 알림 | 임계값 설정, 이슈 자동 생성 |
| 12 | 스프린트 지표(Cycle Time, Velocity, Burndown) 통합 | 분석 스크립트, 차트 |
| 13 | 다른 공개 저장소에 적용해 검증 | 적용 사례 2건 |
| 14 | 문서화 | 사용 가이드, CONTRIBUTING |
| 15 | 버그 수정 및 안정화 | v1.0 릴리스 후보 |
| 16 | **최종 발표** | v1.0 릴리스, 발표 자료 |

1학기에는 단일 저장소 기준으로 수집부터 보고서까지 완성하는 데 집중하고(1~8주), 이후 다중 저장소·알림·패키징으로 확장한다(9~16주).
